# 反汇编

```c
__int64 __fastcall main(int a1, char **a2, char **a3)
{
  unsigned int size; // [rsp+1Ch] [rbp-A4h]
  _BYTE flag[64]; // [rsp+20h] [rbp-A0h] BYREF
  char format[88]; // [rsp+60h] [rbp-60h] BYREF
  unsigned __int64 v7; // [rsp+B8h] [rbp-8h]

  v7 = __readfsqword(0x28u);
  if ( non )
    exit(0);
  memset(flag, 0, sizeof(flag));
  memset(format, 0, 0x50u);
  init_0();
  read_flag(flag);
  puts("Input your name size: ");
  size = read_0("Input your name size: ");
  if ( size > 0x80 )
    exit(-1);
  puts("Input your name: ");
  read_1(format, size);
  printf("Your name is :%s", format);
  puts("Now you have one time to change your name.");
  read_1(format, size);
  blind(format);
  printf(format);
  non = 1;
  return 0;
}
```
主逻辑在`main`函数中，这里有一处溢出写，两个可控的printf，一处为格式化字符串，一次可控参数。

有意思的是下面这个函数，先来看一些前置知识：
- `0` = stdin（标准输入）
- `1` = stdout（标准输出）
- `2` = stderr（标准错误）
```c
unsigned __int64 blind()
{
  unsigned __int64 v1; // [rsp+8h] [rbp-8h]

  v1 = __readfsqword(0x28u);
  dup2(0, 2);
  close(1);
  open("/dev/null", 1);
  dup(1);
  return __readfsqword(0x28u) ^ v1;
}
```

`dup2(0, 2);`

把 `0` 号描述符复制到 `2` 号。  
效果是：`stderr` 不再指向原来的错误输出，而是和 `stdin` 指向同一个对象。
也就是：
- `2` 被关闭并重定向到 `0`
- 以后往 `stderr` 写东西，实际会写到 `stdin` 对应的那个文件/终端上

`close(1);`
关闭 `stdout`。
这时空出来的最小可用 fd 是 `1`。
`open("/dev/null", 1);`
打开 `/dev/null`，第二个参数 `1` 实际上就是 `O_WRONLY`。  
因为 `1` 刚被关掉，所以这次 `open` 大概率会返回 `1`。
于是现在：
- `1 -> /dev/null`
写到 `stdout` 的内容都会被丢弃。

dup(1);
复制 fd `1`，返回当前最小可用的新 fd。
此时：
- `0` 还在
- `1` 是 `/dev/null`
- `2` 已经被 `dup2(0,2)` 占用了
所以最小可用的是 **3**，不是 2。  
因此这一句相当于：
- `3 -> /dev/null`
### 最终结果

执行完后大致是：
- `0`：原 stdin
- `1`：`/dev/null`
- `2`：和 `0` 一样，指向 stdin
- `3`：`/dev/null`

### 这段代码的真实效果
- `stdout` 被丢到 `/dev/null`
- `stderr` 被重定向到了 `stdin`
- 又额外创建了一个 `3` 号 fd，也指向 `/dev/null`
所以它**并没有**把 `stderr` 也重定向到 `/dev/null`。

# 思路
主要利用一个在老版本glibc中比较常用的信息泄露：
```c
glibc 2.25及之前

void
__attribute__ ((noreturn))
__stack_chk_fail (void)
{
  __fortify_fail ("stack smashing detected");
}

void
__attribute__ ((noreturn)) internal_function
__fortify_fail (const char *msg)
{
  /* The loop is added only to keep gcc happy.  */
  while (1)
    __libc_message (2, "*** %s ***: %s terminated\n",
		    msg, __libc_argv[0] ?: "<unknown>");
}
libc_hidden_def (__fortify_fail)
```

这里注意看这部分的libc源码，在`__stack_chk_fail`之后，会调用`__libc_message `打印一些东西，而参数`__libc_argv[0] ?: "<unknown>"`中的`__libc_argv[0]`为程序启动的启动路径（输入命令启动时所用路径），在栈上。

所以梳理一下，大致思路为：第一次溢出泄露saved rbp，算出flag地址的偏移，第二次fmt向保存`__libc_argv[0]`指针的地址写入flag的地址。
