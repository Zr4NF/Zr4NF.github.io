# 反编译

菜单题，`add()`限制`size <= 0x20`。

# vuln

vuln 在`edit()`,`snprintf()`参数错位：
```c
snprintf((char *)chunk[idx], (size_t)"%lu", buf, 8);
```
```asm
lea     rsi, maxlen     ; "%lu"
mov     eax, [rbp+idx]
cdqe
lea     rdx, ds:0[rax*8]
lea     rax, chunk
mov     rax, [rdx+rax]
lea     rdx, [rbp+buf]  ; format
mov     ecx, 8
mov     rdi, rax        ; s
mov     eax, 0
call    _snprintf
```

![Pasted image 20260407161645](/assets/ctf/ad84f3e6e1b33d059f5d.webp)

导致可以直接向chunk写入0x100大小的内容，同时能控制fmt，可以向chunk处写入栈上参数进行信息泄露或任意地址写。

# 思路

该题的难点，在于没有给直接的`show()`函数，用于进行地址泄露，所以考虑用stdout去泄露libc地址。
*tips：该方法在2.32及以上版本，引入堆指针保护的宏之后，完全失效*

只要把flag改成`0xFBAD1800`,`_IO_write_base`改成地址A，`_IO_write_ptr `改成地址B。下次调用`puts`，`printf`等函数时，就能将地址A到B的内容泄露出来。

由于`_IO_write_ptr `指向该结构体+131处（`<_IO_2_1_stdout_+131>`）。一般会选择覆盖`_IO_write_base`的低位为该结构体内写有libc指针的部分。

之后：

- 先布置多个 chunk
- 通过堆溢出篡改相邻 chunk 的 size
- 通过 unsorted bin 的切块机制，构造 **unsorted_bin 和 tcache_bin 重叠**
- 再通过污染 fd 指针，让申请有概率命中 **_IO_2_1_stdout_**
- 借助伪造 stdout 泄露 libc
- 随后再次利用 tc poison，把 chunk 分配到 **__free_hook**
- 将 __free_hook 改写为 system
- 把 "/bin/sh" 写到可控位置并 free，实现 system("/bin/sh")
