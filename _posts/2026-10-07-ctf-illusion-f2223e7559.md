# test.exe WP

## 结论

flag：`xmctf{R3a1_w0rld_M47ters}`

## 题目流程

程序表面上看只有一层字符串校验，但实际上是两层：

1. `main` 先检查输入格式。
2. 第一层通过后，会进入一个伪造成功分支。
3. 这个分支实际跳进被 hook 的 `MessageBoxA`，在隐藏函数里做第二层真校验。

所以直接从 `main` 里看到的那串可逆结果是假的 flag。

## 第一层：`main` 中的假校验

`main` 的逻辑很直接：

- 用 `scanf("%25s")` 读入输入。
- 逐字节检查前缀是否为 `xmctf{`。
- 检查最后一个字符是否为 `}`。
- 检查总长度是否为 `25`。

也就是说 flag 结构是确定的：

`xmctf{??????????????????}`

花括号内一共 `18` 字节。

随后程序构造出一段 18 字节目标数据：

```c
v5[0] = -2063922475;
v5[1] = -416510198;
v5[2] = 1045879079;
v5[3] = -1423348493;
v6    = 21529;
```

再调用：

```c
sub_140001440(Destination, v8, v5)
```

其中：

- `Destination` 是用户输入花括号内的 18 字节
- `v8 = "nev_gona_give_up"`
- `v5 + v6` 拼起来是比较目标

反编译 `sub_140001440` 后可以看出它是标准 RC4：

- 先初始化 `S[256]`
- 再用 key 做 KSA
- 然后做 PRGA
- 最后将结果与目标字节逐个比较

因此把目标密文用 key `nev_gona_give_up` 反解，可得到：

`nev_gona_letydown\x07`

拼回去是：

`xmctf{nev_gona_letydown\x07}`

这串结果明显很怪，最后还有不可见字节。关键是，这一层“校验成功”后程序并没有正常结束，而是继续走到了另一个隐藏分支，所以它只是障眼法。

## 第二层：隐藏的真校验

程序启动早期会执行 `sub_140001000`，它做了一件关键的事：

- 动态获取 `user32!MessageBoxA`
- 保存原始函数前 14 字节
- 用一段跳板代码把 `MessageBoxA` 改写成跳转到 `sub_1400010F0`

也就是把 `MessageBoxA` 给 hook 了。

于是 `main` 第一层成功后执行：

```c
MessageBoxA(0, &Text, "Illusion", 0);
```

表面看像弹窗，实际上会跳进 `sub_1400010F0`。

### `sub_1400010F0` 在做什么

这个函数先把用户输入拷贝出来并做填充，然后调用两次 `sub_1400019E0`。

继续追进去：

- `sub_1400019E0 -> sub_140001A00`
- `sub_140001A00` 里能看到非常明显的 AES 特征

包括：

- 16 字节 state
- SBox 查表 `byte_14001D440`
- ShiftRows
- MixColumns
- AddRoundKey
- 共 10 轮

所以这里做的是 AES-128。

### AES 参数恢复

`sub_1400010F0` 中给出的 key 材料是：

```c
v77[0] = 0x34123412;
v77[1] = 0x34123412;
v77[2] = 0x34123412;
v77[3] = 0x21534541;
```

按小端拼起来就是：

`12341234123412341234123441455321`

对应 ASCII 可理解为：

`1234123412341234` + `AES!`

函数还会检查加密后的 32 字节结果是否等于固定密文：

```text
f2 7b 7e 75 b4 5c 08 fa 19 3c 8a 4a 04 f8 1f 67
1b 05 9c e7 27 40 78 6d 28 f6 a8 b8 06 c6 c5 51
```

由于输入主体长度是 18 字节，所以会先按 PKCS#7 补到 32 字节，再做 AES-128-ECB。

因此直接对这 32 字节密文用上述 key 解密，就能得到真实明文：

`R3a1_w0rld_M47ters`

拼回去就是最终 flag：

`xmctf{R3a1_w0rld_M47ters}`
