# 反编译

经典的菜单题，chunk和size数组在 .bss 段。

```c
__int64 add_chunk()
{
  signed int idx; // [rsp+Ch] [rbp-14h]
  signed __int64 size; // [rsp+10h] [rbp-10h]

  write_str("idx : ");
  idx = read_long();
  if ( (unsigned int)idx >= 0x20 )
    return write_str("invalid idx\n");
  write_str("size : ");
  size = read_long();
  if ( size <= 0x44F || size > 0x550 )
    return write_str("invalid size\n");
  chunks[idx] = malloc(size);
  if ( !chunks[idx] )
  {
    write_str("malloc failed\n");
    _exit(1);
  }
  sizes[idx] = size;
  return write_str("done\n");
}
```

`add()`函数限制了 chunk 的数量为 0x20 个，size 范围为`( 0x4ff , 0x550 ]`。

# vuln

漏洞在`edit()`中，有`off by one`
```c
__int64 edit_chunk()
{
  _BYTE *chunk; // rbx
  unsigned int idx; // [rsp+Ch] [rbp-14h]

  write_str("idx : ");
  idx = read_long();
  if ( idx >= 0x20 )
    return write_str("invalid idx\n");
  if ( !chunks[idx] )
    return write_str("empty\n");
  write_str("content : ");
  chunk = (_BYTE *)chunks[idx];
  chunk[read(0, chunk, sizes[idx])] = 0;        // off by null
  return write_str("done\n");
}
```

# 思路
## step1
通过unsorted bin的残余指针泄露 libc 和堆地址。

## step2

利用`off by null`用类似 House of Einherjar 的方式获取三个悬垂指针。

注意高版本的如下检测：

dele 时：
```c
static void_int_free_merge_chunk (mstate av, mchunkptr p, INTERNAL_SIZE_T size)：

 if (__glibc_unlikely (!prev_inuse(nextchunk)))
    malloc_printerr ("double free or corruption (!prev)");
```

可以通过如下方式构造绕过：
```python
    edit(9,b'\0'*0x4f8 + p64(0x21))
```

add 触发时：
```c
static void
unlink_chunk (mstate av, mchunkptr p)

  if (__builtin_expect (fd->bk != p || bk->fd != p, 0))
    malloc_printerr ("corrupted double-linked list");

if (!in_smallbin_range (chunksize_nomask (p)) && p->fd_nextsize != NULL)
    {
      if (p->fd_nextsize->bk_nextsize != p
	  || p->bk_nextsize->fd_nextsize != p)
	malloc_printerr ("corrupted double-linked list (not small)");
```

可以通过如下构造绕过
```python
    fake_chunk = flat(
        {
            0:      chunk8_addr - 0x18,
            0x8:    chunk8_addr - 0x10,

            0x20:   chunk8,
            0x450:  0x460,
        },
        filler=b"\0",
    ).ljust(0x458, b"\0")
	edit(8, fake_chunk)
```

## step3

通过残余指针 largebin at 打 tc 的`mp_`结构体的`mp_.tcache_bins`，使大 chunk 能进 tc。

## step4

一次 tc poision 打 libc 的 environ 泄露栈地址，最后一次直接通过`edit()`劫持`read()`的返回地址，打rop。

*tips：这里打`edit()`的返回地址，调用`add()`触发攻击时，会因为 chunk 地址对齐，tc 清空 key 值等问题，导致损毁局部变量，不能进行正常`edit()`，如果将申请地址设置的太低，会直接覆盖`read()`函数的返回地址，不如直接打`read()`函数的返回地址*
